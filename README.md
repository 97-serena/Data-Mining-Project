# Data Mining Project: Telecom Customer Churn

Predict whether a telecom customer will churn, and investigate:
1. Do usage, usage-change and service-quality features improve prediction beyond customer and billing features?
2. Which tenure/spending groups contain the most missed churners (false negatives)?

**Data:** Cell2Cell telecom churn dataset, `cell2celltrain.csv`: 51,047 labelled customers × 58 columns, churn rate 28.8%. The original holdout file has no labels and is not used.

The data file is not stored in this repository. Download `cell2celltrain.csv` from our [Google Drive folder](https://drive.google.com/drive/folders/1oVlHRakuFTE_EgKDbQ75KSdIqoTyB_IR) and put it into the `dataset/` folder.

## Repository structure (main)

```

  split.csv            fixed 80/20 train/test split (CustomerID -> train/test), do not change
```

### Phase 1: individual data exploration (current)

This phase is our preparatory exploration of the dataset. Everyone goes through **all 56 features** independently, so that we all know the data before writing the proposal.

**Deadline: 11 October, 10:00 (German time)**

The material for this phase is on the `exploration` branch:
- `eda/eda_template.ipynb`: the template notebook (feature groups, cross-group checks, decision table). **Do not edit this file**; it is the shared starting point for everyone.
- `src/eda_utils.py`: helper functions used by the template
- `eda/summaries/`: where the decision tables (CSV, one per person) are collected

Each person hands in two files:
- `eda/eda_<yourname>.ipynb`: your notebook with your findings
- `eda/summaries/eda_summary_<yourname>.csv`: your decision table

**Steps**
1. Get the `exploration` branch on your computer (clone the repo, then `git checkout exploration`) and download the data into `dataset/` (see Setup).
2. Make a copy of the template on your computer, rename it to `eda/eda_<yourname>.ipynb`, and work only in this copy. Never write your own work into `eda_template.ipynb`, otherwise the others lose the original template.
3. Run your notebook section by section and write your findings in the cell under each section.
4. Fill in the decision table at the end, set `NAME` in the last cell to your name, and run it. Your table is saved to `eda/summaries/eda_summary_<yourname>.csv`.
5. Clear all outputs and upload your two files to the `exploration` branch, using **one** of these options:

   **Option A: git**
   ```bash
   git pull
   git add eda/eda_<yourname>.ipynb eda/summaries/eda_summary_<yourname>.csv
   git commit -m "EDA <yourname>"
   git push
   ```
   Always `git pull` before `git push`, otherwise the push is rejected when someone else pushed first.

   **Option B: GitHub website**
   1. Open the repo on GitHub and switch the branch selector (top left) from `main` to `exploration`.
   2. Open the `eda` folder → **Add file** → **Upload files** → upload your notebook → choose **Commit directly to the `exploration` branch**.
   3. Open `eda/summaries` and upload your CSV the same way.

Everyone uploads to the same `exploration` branch. This causes no conflicts because each person only adds their own files. Do not change the template, `src/` or other people's files. The `exploration` branch is **not** merged into `main`.

### Phase 2: agreed preprocessing (next)

After everyone has finished, we compare the decision tables and agree on one preprocessing plan. It is implemented once on a `preprocessing` branch and merged into `main`. After that, the `exploration` branch is deleted.

## Ground rules

- Use only the training split (`load_train()`); never look at the test split.
- Only edit your own notebook. Shared code lives in `src/`; tell the team before changing it.
- Clear notebook outputs before committing.
- Use `random_state=42` everywhere.
